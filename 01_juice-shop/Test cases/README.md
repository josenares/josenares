<h2>Process to generate test cases</h2>
For QA, it is crucial that SW test has enough coverage on system under test. Therefore, test cases should cover not only expected behaviors or happy paths but also the negative scenarios: how a system reacts when user input is not as expected or required by it. Also, it is required to think of edge/corner cases: how the system behaves when end users decide to enter a set or many sets of wrong data to it; does it handle it well or does it crash or get bricked?
<br><br>
For OWASP Juice Shop test designing, I divided the test scope into 4 main features:
<br><br>
  *User Registration<br><br>
  *Authentication/Log In<br><br>
  *Product search and filtering<br><br>
  *Purchasing<br><br>

  Here, test cases were designed so each component listed above includes happy-path, negative and edge scenarios
