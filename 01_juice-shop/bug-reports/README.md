<h1>Bug reports</h1>

<h2><b>Purpose:</b></h2> Describe the format employed to generate bug tickets once they are detected as well to enlist a brief selection of real examples in the Jira platform.
<br><br>


<h2><b>Bug ticket format</b></h2>
So far, the format used to create these bug tickets is described below:
<br>
  <h3>Test environment</h3>
  
  +<b>Operating system (OS) [Windows, MacOS, Linux,...]</b>
  
  +<b>OS version</b>
  
  +<b>Browser [Edge, Firefox, Safari, etc.][Browser version]</b>
  
  +<b>Environment [Prod, UAT, QA, Dev, Staging]</b>
  
  +<b>SW version</b>: Current version of the SW under test.
  
  
  
  +<b>Bug ticket Title:</b> A short sentence of the issue.
  
  +<b>Description:</b> A high-level explanation of the issue (2-3 lines)
  
  +<b>Preconditions:</b> List of environment setup required prior to reproduce the issue.
  
  +<b>Steps to reproduce:</b> List the steps to recreate the issue
  
  +<b>Expected results:</b> Describe the expected result for each step reproduced in the last section.
  
  +<b>Observed results:</b> Describe the observed result for each step reproduced in the last section.
  
  +<b>Additional notes:</b> This section is intended to explain the reasons why the current issue is classified as defined in the ticket corresponding fields (Severity and Priority)

  +<b>Evidences attached to ticket:</b> [Video files, logs, screenshots supporting what is stated in the bug ticket description]

  +<b>Labels:</b>Add labels to the bug ticket as required, so Jira filtering can easily locate items

  <br><br>
